Representative problem

An HTTP request fans out to three services. If the client disconnects or one required call fails, stop the remaining work.

Reasoning model

How to approach it

  1. Accept context as the first parameter and do not store it in a struct.
  2. Derive a timeout at the request boundary and always defer cancel.
  3. Pass the context into outbound requests and select on ctx.Done in loops or sends.
  4. Use errgroup when sibling errors should cancel the shared group.
Failure modes

What breaks the model

  • Creating context.Background inside a request path and severing cancellation.
  • Using context values for optional function parameters.
  • Returning without stopping tickers, closing bodies, or unblocking goroutines.
Core synthesis

What to remember

Context represents request-scoped cancellation and deadline, so I pass it through every blocking boundary. At the handler I derive a timeout and defer cancel. For related fan-out calls, errgroup gives a derived context that cancels siblings on the first error. Each goroutine must actually observe the context; otherwise cancellation exists only on paper.

go reference 
group, ctx := errgroup.WithContext(request.Context())
for _, endpoint := range endpoints {
    endpoint := endpoint
    group.Go(func() error {
        req, err := http.NewRequestWithContext(ctx, http.MethodGet, endpoint, nil)
        if err != nil { return err }
        response, err := client.Do(req)
        if response != nil { defer response.Body.Close() }
        return err
    })
}
return group.Wait()
