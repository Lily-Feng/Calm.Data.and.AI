Representative problem

Group user events into sessions. A new session begins after more than 30 minutes of inactivity.

Reasoning model

How to approach it

  1. Use LAG to read the prior event time within each user.
  2. Flag the first event or any gap greater than 30 minutes as a new session.
  3. Cumulatively sum the flag to create a session number.
  4. Aggregate by user and session number to produce start, end, and event count.
Failure modes

What breaks the model

  • Using greater-than-or-equal when the requirement says more than 30 minutes.
  • Mixing timestamp time zones.
  • Trying to nest window functions in one expression on engines that disallow it.
Core synthesis

What to remember

Sessionization is a gaps-and-islands problem. I first identify gaps using LAG, then convert each boundary into 1. A running sum of those flags within a user produces the island ID. Keeping these as separate CTEs makes the ordering and window stages clear and portable.

sql reference 
WITH gaps AS (
  SELECT events.*,
    LAG(event_at) OVER (PARTITION BY user_id ORDER BY event_at) AS prev_at
  FROM events
), boundaries AS (
  SELECT gaps.*,
    CASE WHEN prev_at IS NULL
      OR event_at > prev_at + INTERVAL '30 minutes' THEN 1 ELSE 0 END AS starts_new
  FROM gaps
)
SELECT boundaries.*,
  SUM(starts_new) OVER (PARTITION BY user_id ORDER BY event_at) AS session_id
FROM boundaries;
