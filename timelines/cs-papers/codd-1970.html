What Codd was actually arguing against

In 1970 the working data stores were hierarchical and network databases, where a query was a program that followed pointers. The access path was written into the application. Reorganising storage for performance meant rewriting every program that touched it, and the cost of that coupling was the real subject of the paper.

Three independences

  • Ordering independence. A relation is a set. Nothing in the meaning of the data depends on row order.
  • Indexing independence. Indexes are a performance decision, invisible to the query's meaning.
  • Access-path independence. The application states what it wants; the system chooses how.

The third is the expensive one, and it is the reason relational systems needed a query optimiser at all. IBM's System R spent six years finding out how hard it is to make that promise good.

Why the model outlived its critics

Every generation has declared the relational model finished — object databases, XML stores, the NoSQL decade, the data lake. Each time, the application-side cost of hand-written access paths reappeared, and each time the industry rebuilt a declarative query layer on top: HiveQL over MapReduce, Spark SQL over RDDs, SQL endpoints over object storage, table formats bringing transactions back to the lake.

The pattern is consistent: a new storage substrate wins on cost or scale, loses on developer productivity, and reacquires a relational interface within about seven years.

What to carry away

  • Physical independence is what you buy with a query optimiser. When you hand-tune access paths, you are spending it back.
  • Normalisation is about update anomalies, not about elegance — denormalise deliberately, for a read pattern you can name.
  • If a new store has no declarative layer, budget for the one you will end up writing.
