Format, then catalog

The 2017-2023 argument was about table formats: Delta Lake, Apache Iceberg, and Apache Hudi. They solve the same problem (a transaction log or manifest tree over Parquet files) in different ways. By 2024 the formats had largely converged on features, and tools such as Delta UniForm could expose one table under several formats. The question then shifted one layer up.

What a catalog decides

  • Which tables exist, and where their metadata lives.
  • Who can read or write them: permissions, row filters, column masks.
  • Which engines may talk to them, and through what protocol (for Iceberg, the REST catalog specification).
  • Where lineage and audit history are recorded.

Control of the catalog is control of governance, and the shortest path from a table to the compute that queries it.

June 2024

The two companies' annual conferences fell in the same week. Databricks announced the acquisition of Tabular, the company founded by Iceberg's original creators, and open-sourced Unity Catalog. Snowflake announced Polaris, an open catalog implementing the Iceberg REST specification, and later donated it to the Apache Software Foundation.

What to carry away

  • Storage format is now the less contested layer. Catalogs are where governance and lock-in live.
  • "Open" is only useful if an unrelated engine can actually read and write the table through a standard protocol. Test that, rather than trusting the announcement.
  • For a customer, the practical advice is to keep the data in an open table format and treat the catalog as a decision you may need to revisit.
