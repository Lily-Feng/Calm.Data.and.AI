The opposite bet

Spark is an open-source engine that you point at files you own. Snowflake started from the other end: a closed, fully managed SQL warehouse built for the cloud, where the user never sees a cluster, an index, or a file. Its three founders brought the relevant history with them. Benoit Dageville and Thierry Cruanes were Oracle architects; Marcin Żukowski co-created Vectorwise, a vectorised, columnar engine descended from the MonetDB/X100 research at CWI.

Three layers

LayerWhat it doesWhy it matters
StorageColumnar, immutable micro-partitions in cloud object storage, with min/max metadata per column.Queries skip partitions that cannot match (pruning). Immutability gives Time Travel and zero-copy cloning almost for free.
ComputeIndependent virtual warehouses that scale up, scale out, or suspend.Many teams query one dataset without contending for the same machines. You pay for compute only while it runs.
Cloud servicesOptimiser, metadata, transactions, security, result cache.The shared brain. It is also why a repeated query can return instantly without touching a warehouse.

Why separating storage and compute mattered

Hadoop clusters and classic warehouses both bound storage and compute to the same machines. To store more, you bought compute you did not need; to run more queries, you bought storage you did not need. With object storage underneath and elastic compute on top, each scales with its own driver: storage with the data, compute with the questions being asked.

What it gave up

  • Openness. The original storage format was proprietary, so other engines could not read the data directly. Most of Snowflake's later history (Snowpark, Iceberg Tables, Polaris, Snowpark Connect for Spark) is about reducing that gap.
  • Control. There is little to tune. That is a feature until a workload needs something the service does not expose.

What to carry away

  • The three layers are the standard architecture answer. Be able to say what each does and give one consequence for each.
  • Snowpark looks like PySpark but compiles to SQL executed inside Snowflake. The API resemblance is real; the execution engine is not Spark.
  • Vectorised execution has been part of Snowflake's lineage from the start; Databricks reached the same idea later with Photon.
