# Calm Data and AI — Agent Guide

Calm Data and AI is a released static engineering knowledge atlas. Keep it simple enough to run from any static file server and deploy directly to GitHub Pages.

## Product boundaries

The active focus areas are:

1. Cloud systems, organized by topic with AWS/Azure/GCP translations
2. Data platforms: Databricks, Snowflake, and Fabric
3. Python interview patterns
4. SQL reasoning patterns
5. Go concurrency

Do not add frameworks, package managers, build systems, servers, authentication, remote persistence, or browser storage unless the user explicitly asks.

Do not add completion states, streaks, review queues, mastery scores, or other learning-progress mechanics. The product is a reference and concept map, not a tracker.

## Knowledge architecture

The taxonomy, guide metadata, and guide content are three separate layers:

- `data-ai-knowledge-graph.yaml` is the source of truth for the broad seven-layer field atlas shown on the homepage, including its optional MicroStrategy lens (`mstr` on layers, sub-domains, concerns and topics — see `schema.lenses`). `data-ai-knowledge-graph.json` and `js/data-ai-knowledge-graph.js` are derived exports: regenerate both with `python3 scripts/export-knowledge-graph.py` (it also validates ids, edges and lens values) rather than editing them by hand.
- `js/knowledge-atlas-content.js` holds homepage editorial content that is not taxonomy: role trails, guided questions, the 2004–2023 modern-stack milestones and editorial notes. Every reference is a topic id; unknown ids are dropped with a console warning.
- `js/atlas.js` defines domains, clusters, concepts, and graph-to-guide connections.
- `js/manifest.js` holds `TRACKS` and guide metadata only (`id`, `track`, `type`, `title`, `difficulty`, `minutes`, `summary`, `tags`, `bodyUrl`) — no guide body content.
- `guides/<id>.html` holds each guide's actual body as a freeform HTML fragment, authored directly rather than as JS object fields. `guides/README.md` is the authoring contract (one `<article class="guide-content">` wrapper, no `<script>`/inline handlers/full document, asset paths relative to `index.html`, repo-owned content only).
- `KNOWLEDGE_GRAPH_PLAN.md` records the proposed high-level integration and expansion plan.
- `scripts/migrate-guides.mjs` was the one-time script that split the old `js/knowledge.js` (TOPICS-as-JS-objects) into the current manifest + fragment layout. It's a reference, not part of the deploy path.
- A topic belongs to exactly one track.
- Cloud notes should teach a vendor-neutral concept first and translate it to AWS, Azure, and GCP within the fragment.
- Data-platform notes should compare products by workload and trade-off, not repeat marketing feature lists.
- Python, SQL, and Go notes should include a representative problem and a reusable reasoning pattern. Add a compact code panel (see `guides/README.md`) when code materially helps.

Every entry in `js/manifest.js` must include:

- a stable, unique `id`
- `track`, `type`, `title`, `difficulty`, and estimated `minutes`
- a one-sentence `summary`
- useful search `tags`
- `bodyUrl` pointing at its `guides/<id>.html` fragment

Every guide fragment should read as one deep, reusable note — a representative problem, an ordered reasoning sequence, failure modes, and a concise synthesis — rather than several product-specific fragments, but the HTML format doesn't enforce a fixed shape.

## Taste of the Past (timeline) architecture

`timeline.html` hosts the **Taste of the Past** series. It is a second page
with its own stylesheet and its own ES-module
entry point. It shares `css/styles.css` and the shell markup with the atlas but
touches none of `js/app.js`.

- `js/timeline/` is a **component**, not a page. It renders from a spec object
  and reports back through callbacks; it must not fetch data, read the URL, or
  know about Calm Data and AI guides. Page concerns — loading JSON, direct links,
  the sidebar, jumping into the atlas — live in `js/timeline-page.js`.
- `data/timelines/series.json` is the series index: it lists the timelines and
  drives the sidebar navigation. `timeline.html` without a query is the quiet
  series home; `timeline.html?series=<id>` renders exactly one rail. Adding a
  timeline should never require editing `timeline.html`.
- `data/timelines/<id>.json` is the authored layer. `js/timeline/schema.js`
  documents every field and is the only place that parses authored values.
- `timelines/<timeline>/<event>.html` holds optional long-form bodies, under the
  same fragment contract as `guides/` (see `timelines/README.md`). An entry
  without one still gets a complete dialog from its JSON.
- `public/timeline/<timeline>/*.svg` contains committed covers. Most sets are
  generated by `scripts/make-covers.mjs`; `data-platforms` has bespoke SVGs
  generated by `scripts/make-data-platform-covers.mjs`. These scripts are
  authoring tools, not part of the deploy path.
- `scripts/check-timelines.mjs` validates the series. Entry ids must be unique
  across every timeline, not just within a file — the page deep-links entries as
  `#event=<id>` against all rails at once, so a collision silently opens two
  cards. Run it after touching any timeline data.

Rules for changing the component:

- Keep the module boundaries: `schema.js` parses, `scale.js` positions,
  `styles/*` draw, `popup.js` presents, `index.js` composes. A style pack owns
  markup; `css/timeline.css` owns pixels, scoped under `[data-style]`.
- Do not reproduce copyrighted source material as timeline art. Generate a
  cover and link out to the original.
- The rail sizes itself from measured card heights (`fitAcross`). That write
  resizes the box the `ResizeObserver` watches, so it must stay idempotent —
  if you touch it, keep the `lastHeight` guard or the page will spin.
- `openGuide()`-style stale-fetch protection applies to entry bodies too:
  `popup.js` guards with a monotonic token so opening entry A then B cannot let
  A's late response overwrite B.
- Preserve keyboard access (arrow keys walk the markers, one tab stop per
  entry), the reduced-motion path, dialog close behaviour, the shareable
  `?series=` page links, and the `#event=` / `#branch=` entry deep links.

## UI architecture

- `index.html` is the broad Data & AI Field Atlas homepage;
  `knowledge-atlas.html` is its direct preview alias (keep the two identical
  apart from canonical/og URLs and the brand link). It is one fixed viewport:
  a 3D layer stack fills the window and three floating panels — the layer
  rail, the details inspector and the control dock — sit above it. Each panel
  can be minimized; on compact screens the rail becomes a chip row/drawer and
  the inspector a bottom sheet.
  - `js/knowledge-atlas.js` (classic script) owns data indexing, panels,
    routing (`#topic=`, `#group=`, `#concern=`, `#layer=` and `?lens=mstr`),
    search and filters, trails, the timeline and every piece of text.
  - `js/atlas-scene.js` (ES module, Three.js) is a component like
    `js/timeline/`: it renders from a spec, takes `update(view)` and reports
    through `onSelect`/`onHover`. It must not read the graph, the URL or the
    panels. Keep the label declutter pass and the reduced-motion path.
  - The page works without the scene: without WebGL, without module support
    or from `file://`, a 2D layer stack fills the stage and every topic stays
    reachable from the rail and inspector.
  - Three.js r160 is vendored under `vendor/three/` (MIT, only the files the
    scene imports) and mapped by the import map in both HTML files.
- `field-notes.html` preserves the detailed domain-map and guide experience
  previously hosted at `index.html`. `timeline.html` remains the timeline page.
  Shared light-DOM Web Components live in `js/components/`:
  `site-header`, `side-navigation`, `search-view`, and `timeline-view`.
  Components own reusable markup and small UI state; page entry points still
  own data loading, routing, and domain behavior.
- `css/styles.css` owns the responsive visual system for field notes and the timeline page, including baseline typography for `.guide-content` fragments. All pages share one dark palette: the `:root` tokens in `css/styles.css` mirror `css/knowledge-atlas.css`, so change both together. In `styles.css`, `--ink` is text colour only — use `--fill-strong`/`--on-fill` for solid emphasis fills, `--line-strong` for emphasis borders, `--on-accent` for text on acid or pastel accents, and tint per-domain/lane colours with `color-mix()` rather than using them as full backgrounds.
- `js/app.js` renders the field-notes overview graph, domain graphs, concept inspector, and search from `js/manifest.js` + `js/atlas.js`, and fetches/injects the matching `guides/<id>.html` fragment when a guide opens. It also preloads every fragment once at startup (`Promise.allSettled`, cached) to build the full-text search index — a fragment that fails to load degrades to metadata-only search for that guide rather than breaking the page.
- There are no external assets and no build step — fetch-based fragment loading works directly against the static file server / GitHub Pages. The one runtime library is the vendored Three.js used by the homepage scene; do not load it (or anything else) from a CDN.

When changing the application, preserve keyboard access, mobile navigation, dialog close behavior, empty states, and deep links for guides and graph concepts. `openGuide()` guards against stale fetches with a monotonic token — if you touch it, keep that guard so rapidly opening guide A then B can't let A's late response overwrite B's content.

## Validation

Before finishing:

```bash
node --check js/manifest.js
node --check js/atlas.js
node --check js/app.js
for f in js/timeline-page.js js/timeline/*.js js/timeline/styles/*.js; do node --check "$f"; done
node scripts/check-timelines.mjs
node --check js/knowledge-atlas.js && node --check js/knowledge-atlas-content.js && node --check js/atlas-scene.js
python3 scripts/export-knowledge-graph.py --check   # graph exports match the YAML
node scripts/make-covers.mjs   # deterministic; leaves the tree clean if art is current
python3 -m http.server 8080
```

Confirm that the page and local assets return HTTP 200, and that a guide's fragment (e.g. `http://localhost:8080/guides/<id>.html`) returns 200 too. If behavior changed, exercise search (including a term that only appears inside a guide body, to confirm full-text search), domain filters, concept selection, guide links, and mobile navigation.

For timeline changes, also open `http://localhost:8080/timeline.html` and check
that no card escapes its rail's track box at both desktop and ~390px widths,
that a marker opens its dialog and loads its `bodyUrl` fragment, that a ⑂ entry
opens exactly one sub-timeline at a time, that arrow keys walk the markers, and
that the console stays clean.
